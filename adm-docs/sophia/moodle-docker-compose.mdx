# Moodle 5.2 com Docker Compose

Este guia apresenta, passo a passo, como executar o **Moodle 5.2** utilizando Docker Compose, desde a instalação inicial até operações avançadas de manutenção, persistência, backups e diagnóstico.

A arquitetura utilizada é composta por:

- Moodle 5.2
- MariaDB
- Redis
- Serviço de backup
- Docker Compose
- Volumes persistentes
- Healthchecks
- Rede interna do Docker

## Arquitetura

```text
                         ┌─────────────────────┐
                         │       Browser       │
                         │  http://localhost   │
                         └──────────┬──────────┘
                                    │
                                    │ :8096
                                    ▼
                         ┌─────────────────────┐
                         │       Moodle        │
                         │  ruseler/alpine-    │
                         │     sophia:5.2      │
                         └───────┬───────┬─────┘
                                 │       │
                     ┌───────────┘       └───────────┐
                     │                               │
                     ▼                               ▼
             ┌───────────────┐              ┌───────────────┐
             │    MariaDB    │              │     Redis     │
             │     :3306     │              │     :6379     │
             └───────┬───────┘              └───────────────┘
                     │
                     │
                     ▼
             ┌─────────────────┐
             │     Backup      │
             │ MariaDB + data  │
             └─────────────────┘
```

# 3. Arquivo docker-compose.yml

O arquivo principal do projeto é:

```text
docker-compose.yml
```

Crie:

```yaml
services:
  redis:
    image: redis:alpine
    container_name: redis
    restart: unless-stopped

  mariadb:
    image: mariadb:lts
    container_name: mariadb
    restart: unless-stopped

    environment:
      MARIADB_ROOT_PASSWORD: moodle_root
      MARIADB_DATABASE: moodle
      MARIADB_USER: moodle
      MARIADB_PASSWORD: moodle

    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci

    volumes:
      - mariadb:/var/lib/mysql

    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      start_period: 1m
      start_interval: 10s
      interval: 1m
      timeout: 5s
      retries: 3

  moodle:
    image: ruseler/alpine-sophia:5.2
    container_name: moodle
    restart: unless-stopped

    environment:
      LANG: en_US.UTF-8
      LANGUAGE: en_US:en

      SITE_URL: https://sophiadev.mini.pc

      DB_TYPE: mariadb
      DB_HOST: mariadb
      DB_PORT: 3306
      DB_NAME: moodle
      DB_USER: moodle
      DB_PASS: moodle
      DB_PREFIX: mdl_

      REDIS_HOST: redis

      REVERSEPROXY: false
      SSLPROXY: true

      MOODLE_EMAIL: admin@host.docker.internal
      MOODLE_USERNAME: admin
      MOODLE_PASSWORD: M@0dl3ing
      MOODLE_MAIL_NOREPLY_ADDRESS: noreply@host.docker.internal

      AUTO_UPDATE_MOODLE: true

      POST_CONFIGURE_COMMANDS: |
        echo 'Starting background Moodle cron loop...'
        sh -c 'while true; do php /var/www/html/admin/cli/cron.php; sleep 60; done' &

    ports:
      - "8096:8080"

    extra_hosts:
      - "host.docker.internal:host-gateway"

    volumes:
      - moodledata:/var/www/moodledata

    depends_on:
      mariadb:
        condition: service_healthy

    healthcheck:
      test:
        [
          "CMD-SHELL",
          "curl -fsS http://localhost:8080/login/index.php >/dev/null || exit 1",
        ]
      interval: 30s
      timeout: 10s
      retries: 20
      start_period: 2m

  backup:
    build:
      context: ./backup

    container_name: moodle-backup
    restart: unless-stopped

    environment:
      MYSQL_HOST: mariadb
      MYSQL_PORT: 3306
      MYSQL_DATABASE: moodle
      MYSQL_USER: moodle
      MYSQL_PASSWORD: moodle

      BACKUP_INTERVAL: 86400
      BACKUP_RETENTION: 7

    volumes:
      - moodledata:/moodledata:ro
      - ./backups:/backups

    depends_on:
      mariadb:
        condition: service_healthy

      moodle:
        condition: service_healthy

volumes:
  mariadb:
  moodledata:
```

# 7. UTF-8 e Moodle

Uma configuração importante é:

```yaml
command:
  - --character-set-server=utf8mb4
  - --collation-server=utf8mb4_unicode_ci
```

Isso configura o MariaDB para utilizar Unicode.

O Moodle exige suporte adequado a Unicode.

Sem essa configuração, uma instalação nova pode apresentar erro semelhante a:

```text
!! unicode !!

All data must be stored in Unicode format (UTF-8).
```

## 7.1 Por que utf8mb4?

`utf8mb4` permite armazenar caracteres Unicode de forma completa, incluindo caracteres que não são representados pelo antigo `utf8` limitado do MySQL/MariaDB.

Por exemplo:

```text
Olá
Moodle
IoT
ESP32
😀
```

# 8. Persistência do MariaDB

O banco utiliza:

```yaml
volumes:
  - mariadb:/var/lib/mysql
```

Isso significa que os dados ficam em um volume Docker:

```text
mariadb
```

O container pode ser removido sem necessariamente perder o banco.

Por exemplo:

```bash
docker compose down
```

não remove os volumes.

# 9. Atenção ao docker compose down -v

O comando:

```bash
docker compose down -v
```

remove também os volumes.

Isso significa que:

```text
mariadb
moodledata
```

serão apagados.

Para desenvolvimento, entretanto, ele é extremamente útil para começar novamente.

# 14. Cron do Moodle

O Compose utiliza:

```yaml
POST_CONFIGURE_COMMANDS: |
  echo 'Starting background Moodle cron loop...'
  sh -c 'while true; do php /var/www/html/admin/cli/cron.php; sleep 60; done' &
```

Isso cria um loop que executa:

```bash
php /var/www/html/admin/cli/cron.php
```

a cada:

```text
60 segundos
```

O cron do Moodle executa tarefas automáticas como:

- processamento de tarefas;
- envio de mensagens;
- processamento de eventos;
- tarefas de plugins;
- manutenção;
- outras tarefas agendadas.

# 16. Por que o backup depende do Moodle?

O serviço de backup utiliza:

```yaml
depends_on:
  mariadb:
    condition: service_healthy

  moodle:
    condition: service_healthy
```

Isso é importante.

Uma configuração como:

```yaml
depends_on:
  - moodle
```

somente indica que o container Moodle deve ser iniciado antes.

Ela não garante que o Moodle esteja instalado.

A sequência desejada é:

```text
MariaDB
   │
   │ ready
   ▼
Moodle
   │
   │ installed + HTTP ready
   ▼
Backup
```

# 18. Dockerfile do backup

Crie:

```text
backup/Dockerfile
```

com:

```dockerfile
FROM alpine:3.22

RUN apk add --no-cache \
    mariadb-client \
    bash \
    tar \
    gzip

COPY backup.sh /usr/local/bin/backup.sh

RUN chmod +x /usr/local/bin/backup.sh

ENTRYPOINT ["/usr/local/bin/backup.sh"]
```

---

# 19. Script de backup

Crie:

```text
backup/backup.sh
```

com:

```bash
#!/bin/bash

set -e

BACKUP_INTERVAL="${BACKUP_INTERVAL:-86400}"
BACKUP_RETENTION="${BACKUP_RETENTION:-7}"

MYSQL_HOST="${MYSQL_HOST:-mariadb}"
MYSQL_PORT="${MYSQL_PORT:-3306}"
MYSQL_DATABASE="${MYSQL_DATABASE:-moodle}"
MYSQL_USER="${MYSQL_USER:-moodle}"
MYSQL_PASSWORD="${MYSQL_PASSWORD:-moodle}"

BACKUP_DIR="/backups"

mkdir -p "$BACKUP_DIR"

while true
do

    TIMESTAMP=$(date +"%Y-%m-%d_%H-%M-%S")

    BACKUP_PATH="${BACKUP_DIR}/${TIMESTAMP}"

    echo "=========================================="
    echo "Starting Moodle backup"
    echo "Date: ${TIMESTAMP}"
    echo "=========================================="

    mkdir -p "$BACKUP_PATH"

    echo "Backing up MariaDB..."

    mariadb-dump \
        --host="$MYSQL_HOST" \
        --port="$MYSQL_PORT" \
        --user="$MYSQL_USER" \
        --password="$MYSQL_PASSWORD" \
        "$MYSQL_DATABASE" \
        | gzip > "${BACKUP_PATH}/moodle.sql.gz"

    echo "Backing up moodledata..."

    tar \
        -czf "${BACKUP_PATH}/moodledata.tar.gz" \
        -C /moodledata \
        .

    echo "Backup completed."

    echo "Applying retention policy..."

    find "$BACKUP_DIR" \
        -mindepth 1 \
        -maxdepth 1 \
        -type d \
        -printf '%T@ %p\n' \
        | sort -n \
        | head -n "-${BACKUP_RETENTION}" \
        | cut -d' ' -f2- \
        | xargs -r rm -rf

    echo "Sleeping ${BACKUP_INTERVAL} seconds..."

    sleep "$BACKUP_INTERVAL"

done
```

```yaml
BACKUP_RETENTION: 30
```

# 41. Importante: volumes existentes

A configuração:

```yaml
command:
  - --character-set-server=utf8mb4
```

é especialmente importante durante a inicialização de uma nova instalação.

Se o volume MariaDB já existir, simplesmente alterar o Compose não converte automaticamente um banco existente.

Para ambiente de desenvolvimento, uma solução é recriar tudo:

```bash
docker compose down -v
```

e:

```bash
docker compose up -d
```

# 45. Restore: conceito

O backup do Moodle possui duas partes:

```text
Backup
├── Database
│   └── moodle.sql.gz
│
└── Files
    └── moodledata.tar.gz
```

Um restore completo precisa restaurar **ambas**.

Restaurar somente o banco não é suficiente.

Restaurar somente `moodledata` também não é suficiente.

---

# 46. Estratégia de restore

O procedimento geral é:

```text
1. Parar Moodle
2. Parar backup
3. Restaurar banco
4. Restaurar moodledata
5. Iniciar MariaDB
6. Iniciar Moodle
7. Verificar funcionamento
```

---

# 47. Parando os serviços

Antes de uma restauração:

```bash
docker compose stop moodle backup
```

MariaDB pode continuar executando durante o restore.

# 48. Restaurando o banco

Supondo:

```text
backups/2026-09-21_03-00-00/moodle.sql.gz
```

```bash
gzip -dc \
  backups/2026-09-21_03-00-00/moodle.sql.gz \
  | docker compose exec -T mariadb \
      mariadb \
      -u moodle \
      -pmoodle \
      moodle
```

# 49. Restaurando moodledata

O restore do volume exige cuidado.

Uma forma segura é utilizar um container temporário.

Primeiro descubra o volume:

```bash
docker volume ls
```

Por exemplo:

```text
moodle-docker_moodledata
```

Depois:

```bash
docker run --rm \
  -v moodle-docker_moodledata:/moodledata \
  -v "$(pwd)/backups/2026-09-21_03-00-00:/backup:ro" \
  alpine:3.22 \
  sh -c '
    rm -rf /moodledata/* &&
    tar -xzf /backup/moodledata.tar.gz -C /moodledata
  '
```

# 51. Backup não é o mesmo que alta disponibilidade

O serviço de backup protege contra:

```text
perda de dados
```

Mas não fornece:

```text
alta disponibilidade
```

Por exemplo:

```text
Servidor
   │
   ├── Moodle
   ├── MariaDB
   └── Backup
```

Se o próprio servidor for destruído, os backups armazenados nele também poderão ser perdidos.

# 52. Regra 3-2-1

Para ambientes importantes, uma estratégia conhecida é:

```text
3 cópias dos dados
2 mídias diferentes
1 cópia fora do ambiente principal
```

Por exemplo:

```text
Servidor
   │
   ├── MariaDB
   ├── moodledata
   │
   └── Backup local
          │
          ├── NAS
          │
          └── Cloud
```

# 54. Utilizando .env

Crie:

```text
.env
```

Por exemplo:

```dotenv
MARIADB_ROOT_PASSWORD=uma_senha_forte
MARIADB_PASSWORD=outra_senha_forte

MOODLE_USERNAME=admin
MOODLE_PASSWORD=uma_senha_admin_forte
```

Então o Compose pode utilizar:

```yaml
MARIADB_ROOT_PASSWORD: ${MARIADB_ROOT_PASSWORD}
MARIADB_PASSWORD: ${MARIADB_PASSWORD}
```

E:

```yaml
MOODLE_USERNAME: ${MOODLE_USERNAME}
MOODLE_PASSWORD: ${MOODLE_PASSWORD}
```

# 57. Reverse proxy

O Compose atualmente publica:

```yaml
ports:
  - "8096:8080"
```

Em produção, pode ser interessante colocar um reverse proxy na frente:

```text
Internet
   │
   │ HTTPS :443
   ▼
Nginx / Traefik / Caddy
   │
   │ HTTP
   ▼
Moodle :8080
```

Isso permite centralizar:

- HTTPS;
- certificados;
- domínios;
- redirects;
- headers;
- múltiplos serviços.

# 67. Resumo

A arquitetura final utiliza:

```text
┌──────────────────────────────────────────┐
│              Docker Compose              │
│                                          │
│  ┌─────────┐    ┌──────────┐             │
│  │  Redis  │    │ MariaDB  │             │
│  └────┬────┘    └────┬─────┘             │
│       │              │                   │
│       │         ┌────▼─────┐             │
│       └────────►│  Moodle  │             │
│                 └────┬─────┘             │
│                      │                   │
│                 moodledata               │
│                      │                   │
│                 ┌────▼─────┐             │
│                 │  Backup  │             │
│                 └──────────┘             │
│                                          │
└──────────────────────────────────────────┘
```

O ponto mais importante é compreender que existem **três níveis diferentes de dependência**:

```text
Container iniciado
       ≠
Serviço disponível
       ≠
Aplicação pronta
```

Por isso o Compose utiliza `healthcheck` e:

```yaml
depends_on:
  condition: service_healthy
```

em vez de depender apenas da ordem de inicialização dos containers.
